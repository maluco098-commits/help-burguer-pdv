PROMPT MESTRE — HELP BURGUER PDV
================================================
OBJETIVO
Construir um sistema PDV (Ponto de Venda) REAL E FUNCIONAL para a lanchonete Help Burguer.
Não criar apenas um protótipo visual. O sistema deve possuir frontend, backend, banco de dados,
autenticação, persistência real, impressão térmica e integração com WhatsApp.

O projeto deve rodar localmente no VS Code e estar preparado para produção.

IDENTIDADE VISUAL
- Marca: Help Burguer
- Usar a logo fornecida em /assets/logo-help-burguer.png.
- Estilo: moderno, premium, profissional, inspirado em hamburgueria na brasa.
- Fundo predominante: preto/grafite.
- Cor principal: dourado/amarelo.
- Cor de destaque: vermelho para ações de alerta/cancelamento.
- Verde para status online, caixa aberto e WhatsApp.
- Interface responsiva para computador, notebook e tablet.
- Evitar excesso de efeitos; priorizar velocidade e legibilidade.

REFERÊNCIAS VISUAIS
Os arquivos:
- /assets/referencia-pdv-desktop-tablet.png
- /assets/referencia-sistema-completo.png
servem como referência de layout e identidade, mas não devem ser copiados literalmente.
Criar uma interface original mantendo a mesma linguagem visual.

STACK RECOMENDADA
Frontend:
- React + TypeScript
- Vite
- Tailwind CSS
- shadcn/ui ou componentes equivalentes
- Lucide React para ícones
- React Router
- TanStack Query
- React Hook Form + Zod

Backend:
- Node.js + TypeScript
- NestJS ou Express bem estruturado
- API REST
- WebSocket/Socket.IO para alertas em tempo real

Banco:
- PostgreSQL
- Prisma ORM
- Migrações versionadas
- Seed inicial com produtos da Help Burguer

Autenticação:
- Login com usuário e senha
- Senhas com hash seguro
- JWT + refresh token
- Controle de permissões
- Perfil inicial: CAIXA/OPERADOR e ADMIN

REGRAS IMPORTANTES PARA A IA DO VS CODE
1. Primeiro analisar a estrutura existente antes de modificar arquivos.
2. Não apagar código funcional sem necessidade.
3. Criar arquivos de forma organizada.
4. Não criar apenas telas falsas.
5. Implementar API e persistência real.
6. Se alguma integração externa exigir credenciais, criar o adaptador e instruções, mas nunca inventar credenciais.
7. Usar componentes reutilizáveis.
8. Manter TypeScript estrito.
9. Corrigir erros de compilação antes de finalizar cada etapa.
10. Sempre informar quais arquivos foram criados/alterados.
11. Implementar em etapas:
   Etapa 1: estrutura + banco + autenticação
   Etapa 2: cardápio + produtos
   Etapa 3: tela de venda + pedidos
   Etapa 4: caixa + despesas
   Etapa 5: precificação
   Etapa 6: impressão térmica
   Etapa 7: WhatsApp + WebSocket + alertas
   Etapa 8: relatórios
   Etapa 9: testes + segurança + produção
12. Depois de cada etapa, executar os testes/build e corrigir os problemas.
13. Não considerar o projeto concluído enquanto o fluxo completo:
   login → abrir caixa → montar pedido → finalizar → registrar pagamento →
   salvar no banco → imprimir → aparecer no histórico
   não estiver funcionando.

PRIMEIRA TAREFA
Antes de escrever código, faça uma análise do ambiente do projeto.
Depois proponha a estrutura de pastas.
Em seguida crie a base funcional e avance etapa por etapa.
No final de cada etapa, mostre:
- o que foi implementado;
- arquivos criados;
- arquivos alterados;
- comandos executados;
- pendências reais.
